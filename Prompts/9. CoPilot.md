Generic RTL coverage: I can't say the branch is close to a complete solution. Layout mirroring (BiDiMode, ParentBiDiMode, mirrored drawing and hit-testing, flipped icons, popups and tables) is language-independent and works. The custom-painted text editors don't do bidi reordering. Caret, selection and hit-testing assume pure RTL text, so mixed-direction text (Arabic or Hebrew with English words or digits) will probably be wrong. A fix would need DirectWrite or Uniscribe for caret and hit-test data.

IME change: it isn't an RTL fix. It's generic for IME-based input (Korean, Japanese, Chinese), which are left-to-right. It has not been tested with a real IME.

Recommendation: get native Arabic or Hebrew speakers to test the demos, and add mixed-direction text tests for the editors.

In what way could the IME affect LTR languages and what is meant by IME

----------

IME means Input Method Editor. It's the Windows component that lets you type languages with far more characters than a keyboard has, such as Korean, Japanese and Chinese. You type phonetic keystrokes and the IME turns them into characters, showing an in-progress "composition" that you confirm. Those languages are left-to-right, so my wording was loose: the change is meant for LTR languages, and RTL languages like Arabic don't use an IME.
The change only does something when an IME is actually composing. For a plain English or other keyboard-typed user, no composition messages arrive. The new code still runs in small ways on every text field. It hides the IME's own composition window, repositions IME windows when the field gets focus, and checks for an unfinished composition when you click or leave the field, and those checks do nothing when no composition is active. The risk is therefore low for English typing, but it isn't zero, since it's new code in the shared edit path that hasn't been tested with a real IME. For Korean, Japanese and Chinese users it changes behaviour a lot: text now appears inline instead of in a separate window. That is why I'd keep it out of an RTL-only merge until someone with a real IME has tested it.
